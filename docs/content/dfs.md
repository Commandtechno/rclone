# {{< icon "fab fa-discord" >}} dfs

dfs stores file contents as Discord attachments and keeps the directory
tree in postgres. It's the format written by the `fsexp` and `fs-new`
tools, so rclone can read and write the same store.

- Files are split into 10 MiB chunks. Up to 10 chunks are posted per
  message, in private threads of one channel. Files from older tools
  that used 25 MiB chunks read fine.
- Metadata lives in the `directories` and `files` tables. Deletes are
  soft (`deleted_at`), matching gorm. Chunks are never deleted from
  Discord, so server-side copies just share them.
- Resolved CDN urls are cached in the `chunk_urls` table if it exists
  (`fs setup` creates it).
- Files in directories marked `encrypted` (or under one) are encrypted
  with AES-256-CTR per chunk, compatible with `fs-new`.

## Configuration

```console
rclone config create mydfs dfs \
    discord_token "Bot <token>" \
    channel_id 123456789012345678 \
    database_url "postgres://user:pass@host:5432/db"
```

Then for example:

```console
rclone lsd mydfs:
rclone copy ~/photos mydfs:backups/photos -P
rclone mount mydfs: ~/dfs
```

The token is sent exactly as given, so include the `Bot ` prefix for a
bot token.

## Limitations

Only per chunk md5s are stored, so dfs has no whole file hash and
rclone checks transfers by size and modification time.

Modification times are stored to the microsecond.

Each transfer buffers `--dfs-upload-concurrency` chunks when uploading
and `--dfs-download-concurrency` chunks when reading, 10 MiB each.
